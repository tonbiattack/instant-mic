# instant-mic 仕様書 (v0.1 / MVP)

## 目的
Android端末を、離れた場所からWindows PCへ低操作数で音声入力・定型キー操作できるリモート入力端末にする。Bluetoothイヤホンは音声出力専用のまま使えるようにする。

## UX原則
- 一度ペアリングした端末は最小操作で再接続できる
- 音声入力中であること、認識中であること、送信済みであることを明示する
- キーボードに触れずに「指示→送信」まで完了する
- 不要な録音履歴・配信機能は追加しない

## MVPスコープ
1. Androidアプリ（Kotlin）：音声認識で日本語の発話をテキストに変換。ワンタップ開始・停止。認識中/接続中の表示。
2. Windows常駐アプリ（Go）：ローカルネットワーク上でAndroidからの認証済みメッセージを受信。現在フォーカス中の入力欄へUnicodeテキストを挿入し、定型キーを送信。
3. Wi-Fi接続：同一LAN上で初回ペアリングし、以後は再接続。接続切れの検出、再試行。
4. 音声コマンド：デフォルト接頭語「コマンド、」付きの場合だけ操作として解釈する。
   - 「コマンド、送信」→ Enter
   - 「コマンド、改行」→ Shift+Enter
   - 「コマンド、削除」→ Backspace（音声の「削除」）
   - 「コマンド、行削除」→ 現在行を削除（Home → Shift+End → Delete）
   - 「コマンド、取り消し」→ Ctrl+Z、「コマンド、全選択」→ Ctrl+A
   - 詳細は「音声コマンド一覧」を参照
5. 音声認識に失敗した場合はキー操作を行わず、再試行可能とする。
6. 連続音声入力：停止操作まで、発話ごとに自動で聞き取りを再開する（既定で有効）。
7. 開始・終了の触覚フィードバック：聞き取り開始可能になった時点で1回、聞き取り終了で2回振動する。
8. 接続操作の簡略化：初回はQRコードを読み取るだけでペアリングし、2回目以降はアプリ起動時に同じPCへ自動接続する（LAN内の自動検出に対応）。

## 音声コマンド一覧

接頭語（既定「コマンド」）の後に、区切り（「、」や空白）または連続した語で続ける。**正規化後の全体一致**のみ実行する。

| 発話 | 操作 |
| --- | --- |
| コマンド、送信 / コマンド、エンター | Enter |
| コマンド、改行 | Shift+Enter |
| コマンド、削除 / バックスペース | Backspace |
| コマンド、前の単語削除 | Ctrl+Backspace |
| コマンド、行削除 | 現在行を削除（Home → Shift+End → Delete） |
| コマンド、デリート | Delete |
| コマンド、上 / 下 / 左 / 右（アップ / ダウン / レフト / ライト） | ↑ / ↓ / ← / → |
| コマンド、コピー / 貼り付け（ペースト）/ 切り取り | Ctrl+C / Ctrl+V / Ctrl+X |
| コマンド、やり直し | Ctrl+Y |
| コマンド、タブ切り替え | Ctrl+Tab |
| コマンド、取り消し / 取消 | Ctrl+Z |
| コマンド、全選択 | Ctrl+A |
| コマンド、言い直し / 言直し | 直前にPCへ入力したテキストを取り消す |
| コマンド、3回削除 / 削除3回 / 三回削除 | 削除を3回（上限5回、対象は削除・デリート・カーソル移動・前の単語削除） |

同じ操作に複数の言い方があるものは、**キー名をカタカナで言っても認識される**（「コマンド、エンター」「コマンド、バックスペース」「コマンド、アップ」など）。誤認識しやすい「上」より「アップ」の方が通りやすい場合はこちらを使う。

「行削除」はアプリごとにショートカットが異なるため、既定では **Home → Shift+End → Delete** で行全体を選択して削除する。VS Code などはこの操作で行が消えるが、ソフトウェアによっては行末の文字だけが消える。アプリ別の割り当てはカスタムコマンドで置き換えられる。

### 言い直し（直前の入力を取り消す）

音声認識を誤ったとき、PCのキーボードに触らずに取り消せる。

- 「コマンド、言い直し」で、**直前にPCへ入力したテキストの文字数ぶん Backspace** を送る
- 対象は直前のテキスト入力のみ。キー操作（送信・削除など）のあとは取り消せない（カーソル位置や文書の状態を PC 側が測れないため）
- 取り消しは1回限り。同じ入力を二重に消さない
- 受信側は自分が記録した文字数と、スマホから届いた件数が一致したときだけ削除する。不一致なら何も消さずに失敗を返す
- 改行を含む入力は、改行も1文字として数える
- 上限は送信上限と同じ4000文字。超える入力はそもそも送信できない

### 句読点の整形

確定したテキストをPCへ送る前に、話した句読点を記号へ置き換える（コマンド判定のあと、通常テキストにだけ適用）。

| 発話 | 変換 |
| --- | --- |
| まる | 。 |
| てん | 、 |
| はてな | ？ |
| びっくりまーく | ！ |
| ころん | ： |
| せみころん | ； |
| すらっしゅ | / |
| かっこ 〜 かっことじ | （ 〜 ） |
| かぎかっこ 〜 かぎかっことじ | 「 〜 」 |

- 単独で使う記号は、**文末・空白・既存の句読点の直前**にあるときだけ変換する。「まるで違う」「てんぷら」「かっこいい」は変換しない
- かっこ類は開きと閉じが両方そろっているときだけ変換し、対応の取れないかっこを作らない
- 認識結果がすでに句読点で終わっている場合は重複させない（「てん、」→「、、」にしない）
- Android / Go の双方に同じ表を実装している。変換した場合は画面に「認識 → 送信」を並べて表示する

### 誤変換エイリアス

音声認識が「改行」を「開業」と変換する実測があるため、**コマンド単位の明示的な別名**だけを許可する（無制限のあいまい一致・部分一致はしない）。別名は次のとおり。

- 改行 → 開業
- 取り消し → 取消
- 削除 → バックスペース
- 前の単語削除 → 単語削除
- 貼り付け → 貼りつけ

破壊的コマンド（削除・行削除・デリート）には、実測された表記ゆれ以外の別名を追加しない。「開業しました」「コマンド開業について説明して」のような文は通常テキストとして送信される。

### カスタムコマンド

Android の「コマンド」画面から、呼び出しフレーズと呼び出し先のキー操作を登録・編集・削除できる。

- 例：「AIに送信」→ `ctrl+enter`
- キーは `ctrl+enter`、`home>shift+end` のように指定する。`>` で最大8ステップの連続操作になる
- Ctrl / Shift / Alt / Win と、英数字・F1〜F24・Enter/Tab/Escape/Backspace/Delete/Insert/Space/矢印/Home/End/PageUp/PageDown のみ許可
- 標準コマンドと重複するフレーズは拒否し、既存コマンドを意図せず上書きしない
- Ctrl+Alt+Delete は Windows のセキュリティ画面を開くため、送信側・受信側の双方で拒否する
- カスタムコマンドは端末内にだけ保存する（音声・認識結果は保存しない）

## 連続音声入力とライフサイクル

状態は「待機（Idle）」「準備中（Preparing）」「聞き取り中（Listening）」「認識処理中（Processing）」「再開待ち（Resuming）」「失敗（Failed）」に分け、UI と振動をこの状態に一致させる。

1. タップで `startListening` を呼ぶ。`onReadyForSpeech` が来るまでは「準備中」と表示し、振動もしない
2. `onReadyForSpeech` で「聞き取り中」にし、1回振動する（開始の合図）
3. `onEndOfSpeech` で「認識処理中」にし、2回振動する（終了の合図）
4. 確定結果 `onResults` があれば1回だけ送信し、次の認識セッションを開始する
5. 無音・認識結果なし（`ERROR_NO_MATCH` / `ERROR_SPEECH_TIMEOUT`）は回復可能な終了として、250ms〜3秒のバックオフ後に再開する
6. 停止操作のあとは再開しない。`onPause`（画面離脱）でも停止する
7. ネットワーク・マイク系エラーが3回続いた場合はループを止め、理由を表示する
8. 同じ認識結果の二重送信を防ぐため、セッションIDごとに結果を1回しか通知しない

バックグラウンド録音は対象外（画面を開いて使う）。画面OFFや他アプリ使用中の継続受信は別途検討する。

## 起動と操作のショートカット

「すぐ話せる」を優先しつつ、Android のバックグラウンド録音制限は守る。

- **Quick Settings タイル**: タイルをタップするとアプリが前面に開き、そのまま聞き取りが始まる。タイル自体は録音しない（前面の Activity でのみ録音する）
- **起動したらすぐ話す（設定）**: オンにするとアプリを開いた時点で聞き取りが始まる。既定はオフ
- どちらも `onPause` で停止する従来の挙動を変えない（画面を離れたら録音しない）
- マイク権限がない場合は権限要求へ誘導し、許可後に開始する
- タイルはユーザーが手動で追加する（初期状態では追加しない）

## 接続とペアリング

接続の手間を減らしても、認証の強度は落とさない。初回だけ明示的にペアリングし、以後は保存済みトークンで自動接続する。

### 初回: QRペアリング

1. PC側で `p` を押す。6桁コードとQRコードが表示される
2. Android は「QRコードを読み取る」でスキャンするだけ。IP・ポート・コード・指紋の入力は不要
3. QRは `instantmic://pair?...` 形式で、ホスト・ポート・TLS指紋・短寿命のQRシークレット・serverId を含む
4. **長期トークンはQRに含めない**。QRシークレットは1回限り・既定10分で失効し、成功時に6桁コードと同時に無効化される
5. アプリはQRの指紋をTLSハンドシェイク中に照合してからペアリング要求を送る
6. QRを読めない場合は従来の手動入力（IP・ポート・6桁コード・指紋）を代替手段として残す

#### 読み取り手段

- 既定は **Google Code Scanner**（システム提供のスキャナ）。起動が速く、カメラ権限も不要
- Play 開発者サービスがない端末では、アプリ内蔵の ZXing スキャナに自動でフォールバックする
- `instantmic://pair?...` は **他のQRアプリからも開ける**。カメラやQRリーダーで読み取ると本アプリが起動し、ペアリング先の確認画面を出す
- リンク経由でも自動では接続しない。ホスト・ポート・証明書指紋を表示し、ユーザーが「このPCとペアリング」を押したときだけ実行する

### 2回目以降: 自動再接続

- アプリ起動時、保存済みトークンで即座に接続を試みる（6桁コードも指紋認証も不要）
- 同時に mDNS（`_instantmic._tcp`）で同じPCを検索し、IPが変わっていれば新しいアドレスへ切り替える
- 切り替えは保存済み `serverId` と TLS指紋が一致した場合だけ行う
- 別のPCを検出した場合、または証明書が変わった場合は自動接続せず「再ペアリングが必要です」と表示する
- 検出できないネットワークでは保存済みアドレスのまま接続を試みる
- 接続状態は「未接続／接続中／接続済み／検出中／検出不可／再ペアリング必要」で表示し、必要な時だけ「再接続」を押せる
- 未ペアリング端末は検出できてもトークンがないためテキストもキーも送れない

### 起動と終了

- 画面を離れると録音は停止する。戻ると、止める前の状態が続いていれば自動で再開する（バックグラウンド録音はしない）
- 権限ダイアログや回転では停止しない（`onStop` でのみ止める）
- Quick Settings のタイルから開いた場合も同じ

## 危険なコマンドの確認

「送信・削除の前に確認する」を有効にすると、取り返しのつきにくいコマンドだけ確認を挟む。

- 対象: `送信`（Enter）、`削除`/`行削除`/`前の単語削除`、`貼り付け`/`切り取り`
- 対象外: 矢印、コピー、取り消し、タブ切り替え（取り返しがつくため）
- 確認は**タップ**で行う。同じ発話をやり直すと認識器が同じ誤りをする可能性があるため
- 「やめる」を選ぶと何も実行せず、その旨を表示する
- 既定はオフ（従来どおり即実行）



- `-tray` で通知領域のみの常駐起動。メニューから「ペアリング開始（QR表示）」「QRコードを表示」「ペアリング中止」「ログイン時に起動」「終了」を選べる
- **未ペアリングで起動したときは、自動でペアリングを開く**（毎回 `p` を押す手間をなくす）。ペアリング済みなら静かに待ち受ける
- トレイのツールチップに接続状態（未接続／接続中 N台）とペアリング済み台数を表示する
- `-autostart on` でWindowsログイン時の自動起動を登録する（ユーザーのスタートアップフォルダに小さな起動スクリプトを置く方式、オプトイン）
- `-autostart off` で解除、`-autostart status` で状態確認
- `-no-discovery` で mDNS 広告を無効化（手動接続は引き続き可能）

## コマンド解釈
- 認識結果を正規化（前後空白、句読点・表記揺れ）して完全一致判定。部分一致や文中ヒットでは発火させない。
- コマンドと通常テキストの双方を同時に実行しない。通常の発話はテキストとして挿入する。
- 誤送信対策としてコマンド実行前の視覚フィードバックと、必要に応じて「送信」の確認オプションを検討。
- アプリごとにEnterとCtrl+Enterの意味は違うため、送信キー割り当てを将来カスタマイズ可能にする。
- 音声認識の部分結果（interim）ではコマンドを解釈しない。確定結果でのみ実行する。二重送信を防止する。
- 認識された原文と実行したコマンドを画面に表示する（音声データは保存しない）。

## 逐次表示と段階的入力

発話中もAndroid画面に暫定テキスト（部分認識）を表示する。PCへの入力は2段階で扱う。

1. **既定（確定後にまとめて入力）**: 部分結果は画面に表示するだけで、PCへは確定結果だけを送る
2. **区切りごとに早めに入力**: 文末（`。！？`）や、長い発話の句読点で区切れた部分を、確定したフレーズとして先に送る

区切り入力の安全規則は次のとおり。

- 送信済みの文字列は書き換えない。後から届いた部分結果・確定結果が送信済み部分から始まらない場合は、**追加入力せず、画面に「PCの文を確認してください」と表示する**（カーソル移動・フォーカス移動・入力欄の自動補完があるため、Backspaceで巻き戻すと壊す恐れがある）
- コマンドは確定結果だけで解釈する。発話が「コマンド」で始まる（途中でも）場合は、その発話の逐次入力を停止する
- 送信途中で失敗したら、その発話の残りは入力しない（順序が入れ替わるのを防ぐ）
- 括弧（`かっこ` など）が閉じていないフレーズは送らない
- 部分結果に対応しない認識サービスの場合は、従来どおり確定結果のみとなる
- 逐次入力をACKで確認してから次のフレーズを送る。重複・順序入れ替わりは起こさない

## 誤変換の低減

- **認識方式の切替**: 「端末内を優先」と「システム既定（ネットワーク利用可）」を選べる。端末実装がヒントを無視することがあるため、画面には実際の方式（取得できた場合）も表示する
- **複数候補**: `EXTRA_MAX_RESULTS` で複数取得し、候補と信頼度を画面に並べる。**自動で候補を切り替えない**（誤った自動切替は手動選択より悪い）。候補を選んでもPCへは追加入力しない
- **開発用語辞書**: `GitHub`・`Codex`・`SQL`・`Go`・`Nuxt` などの誤変換（`ギットハブ` など）を修正する。規則は次のとおりで、テキストを壊さないことを優先する
  - 日本語（カタカナ）の誤認識だけを置換対象とし、ASCII・コード・URL・メール・`` ` `` 囲みは対象外
  - 最長一致のみ。重ならない
  - 置換後がカタカナで続く場合は置換しない（`ゴール` を `Goール` にしない）
  - `:` や `/` が続く場合はラベル・パスとみなし置換しない
  - 数字だけの語は置換しない
- **無音判定**: 「短め（800ms）／標準（1,200ms）／長め（2,000ms）」から選べる。長めは発話途中の分断を減らす。サービスがヒントを無視する場合があることも画面に明記する
- **語彙ヒント**: 対応する認識サービスには辞書の語を `BIASING_STRINGS` として渡す（未知のキーは無視される）
- **ひらがな出力（オプトイン）**: 漢字に変換せず読みのまま入力する。誤変換の最大要因である漢字選択を消せるため、AI への指示書きと相性が良い
  - 形態素解析（Kuromoji + IPADIC、端末内で動作）で読みを得る。辞書は APK に同梱する
  - 英数字・URL・コード・記号は変換しない。解析器が使えない場合は入力そのまま（設定が無効になるだけ）
  - 辞書補正の後に適用する（`ギットハブ`→`GitHub`→`ぎっとはぶ`）
  - 既定はオフ。日本語の文章を書く用途では漢字のままが自然なため
- 既定は無料・APIキー不要。外部LLM校正は対象外

## メッセージ仕様（案）
- WebSocket over LAN。端末ごとにランダム生成したペアリング秘密情報による認証、TLSまたは安全なローカル通信方式を技術調査で決定。
- type: text / key / ping / ack / error。各操作に一意なIDを付け、ACKと重複実行防止を実装。
- テキスト入力はUnicode対応。IME・日本語・改行、フォーカス未取得時の挙動を検証。
- 外部ネットワークには公開しない。無認証のキー入力受信は禁止。

## 非機能・制約
- プライバシー：必要な権限のみ要求。Android音声認識がクラウド処理になる可能性を明示し、可能なら端末上認識を優先。音声ファイルは保存しない。
- Androidのバックグラウンドマイク権限制約に従う。完全常時待機はMVP対象外。
- Windows側では管理者権限のアプリや一部ゲーム等にキー入力できない場合がある。UAC回避は対象外。
- Windows + Hや独自仮想マイクには依存しない。直接テキスト/キーイベントを届ける。
- 接続遅延、認識確定〜文字挿入の遅延、再接続時間を実測してUXを改善する。

## 受け入れ条件
- 同一Wi-Fi上のAndroidからWindowsのメモ帳へ日本語を音声入力できる
- 「コマンド、送信」でEnter、「コマンド、改行」でShift+Enterを実行できる
- 「コマンド、削除」でBackspace、「コマンド、行削除」で現在行を削除できる
- 通常文に「送信」が含まれても誤実行しない
- 接続断を検知し、操作の送信失敗を知らせる
- 未ペアリング端末からテキスト/キー入力を受け付けない
- BluetoothイヤホンをWindowsの出力にしたまま入力できる
- 無音を挟んで続けて話しても、ボタンを再タップせずに次の発話が入力される
- 停止操作のあとは自動再開しない
- 画面を見なくても、開始・終了を振動で判別できる
- 直前の入力を「コマンド、言い直し」で取り消せる
- 「こんにちはまる」が「こんにちは。」になり、「まるで違う」はそのまま入力される
- Quick Settings タイル、またはアプリ起動でそのまま話し始められる
- QRコードを読み取るだけで初回ペアリングできる
- 2回目以降はアプリ起動から自動接続でき、認証操作が不要
- PCのIPやポートが変わっても、ペアリング済みの同じPCへ自動再接続できる
- 別のPCや証明書が変わったPCには黙って接続しない
- Windowsログイン時の自動起動を設定できる
