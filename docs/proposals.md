### 2. 言い直しコマンドの設計メモ

- 当初は「Backspace を N 回送る」キー操作で実装する案だったが、既存のキー繰り返し上限（5回）を
  迂回する必要があり、誤操作時の被害も大きい。そこで専用メッセージに分離した。
- 受信側は「直前に入力した文字数」を自分で記録し、スマホから届いた件数と**一致したときだけ**削除する。
  これにより、間に別の操作が入った場合や、再送で二重に消す事故を防ぐ。
- キー操作（Enter・Backspace 等）の後は記録を破棄する。カーソル位置や文書の状態を PC 側が
  測れないため、「消せるはず」と推測しない方が安全と判断した。
- 改行を含む入力は改行も1文字として数える（Android の codePointCount と Go の rune 数で一致）。

### 3. 句読点整形の設計メモ

- いちばん誤爆しやすいのが「まる」「てん」が単語の一部になるケース（まるで・てんぷら・かっこいい）。
  そのため変換条件を「文末・空白・既存の句読点の直前」に限定した。話すときに一呼吸置けば
  認識結果に区切りが入るので、実用上は困らない。
- かっこ類は開閉の対応が取れているときだけ変換する。片方だけ変換して
  「（」だけが残る事故を防ぐ。
- 数字の読み（いち・に・さん）は文脈依存で誤爆しやすいため**今回の対象外**。
  必要になったら別イシューで、設定オプトインとして扱う。
- 置換表は Go（`internal/speech/shape.go`）と Kotlin（`TextShaper.kt`）の2か所にあり、
  テストで同じ入出力を検証している。将来ユーザー編集可能にする場合は、表を1か所に集約する
  必要がある（現状は重複を許容）。

## 採択しなかったもの

### 1. 入力先ウィンドウの固定（PIN）

**内容**: PC 側で入力先ウィンドウを選んで固定し、送信直前に前景ウィンドウが一致するか検証する。
一致しなければ入力せずエラーを返す。

**不採用の理由**: ユーザー判断により不要。現状の「フォーカス中のウィンドウへ入力する」で
運用上問題がないため。将来、誤爆が実際に問題になったら再検討する価値はある
（実装は `checkTarget()` にウィンドウハンドル比較を足すだけで小さい）。

## 未採択・保留（今回はイシュー化していない）

| 案 | 内容 | 保留理由 |
| --- | --- | --- |
| 定型文スニペット | 「コマンド、定型1」で登録済み文章を展開 | カスタムコマンドの仕組みを流用できるが、テキスト送出アクションの追加が必要。需要確認後 |
| 複数PCのペアリング管理 | デスクトップ／ノートPCを持ち替える | #10 で serverId ベースの識別が入ったので実装しやすい。利用者が複数PCを持つ場合に |
| 送信履歴（メモリ内） | 直近10件を表示しタップで再送 | 誤送信リカバリに有効。ただし「言い直し」で当初の目的は満たせるため後回し |
| PC側の状態通知 | フォーカスなし等をWindows側でもトースト表示 | スマホのエラー表示で足りるため後回し |
| アプリ別キー割り当て | 前景プロセス名ごとにキー列を切替 | 「行削除」の挙動差を解消できるが、設定 UI とデータ構造の拡張が大きい |
| 音声での長文編集 | 「ここから選択」「その文を削除」 | 選択範囲を扱うプリミティブの設計が必要。規模が大きい |
| 数字の読み上げ変換 | 「いち」「に」→ 1, 2 | 文脈依存で誤爆しやすい。オプトイン前提で別途 |
